## 三、五项改动（根因 + 方案 + 影响面 + 验证）

### 1. 设置里"画了展开箭头，点一下却是切换"

**现象**：设置 → 显示与行为，右侧画着下拉箭头的几行，点一下是把值循环切换，展开不了。

**根因**：`ui/design/src/main/java/xin/dshaa/ui/design/component/Settings.kt:227` 的 `SettingsSelectorRow`
画 `KeyboardArrowDown`，但所有调用点 `onClick` 都是"循环切换/二选一"：

- `ui/native-shell/.../ui/settings/BehaviorScreen.kt:84` —「生成中发送」排队发送 / 插话发送两行；
- `BehaviorScreen.kt:143` — 审批方式（自动允许 / 每次询问）；
- `BehaviorScreen.kt:158` — 外观（跟随系统 / 浅色 / 深色）；
- `BehaviorScreen.kt:177` — 强调色（6 套循环）。

（`ModelConfigScreen.kt:226 / 239 / 421` 是弹窗选择器，语义正确，保留不动。）

**方案**：在 `Settings.kt` 新增真正的展开式选择行：标题 + 当前值 + 箭头；点击展开内联选项列表
（每项单选勾 + 说明，选中即收起；箭头随展开状态旋转，`AnimatedVisibility` 做展开动画）。
改造上面 4 处；"生成中发送"两行合并为一行「发送方式：排队/插话」+ 展开二选一。
**聊天页不新增任何按钮**（用户第 1 条）。

**影响面**：只动 design 组件 + BehaviorScreen。设置键（`send_while_running` / `approval_mode` / `theme_mode` /
`accent_id`）不变；队列/主题/审批逻辑不变。

**验证**：构建 + 真机逐组点开；退出重进、Activity 旋转后值保持；模型页三个弹窗不回归。

### 2. 二级页还能右滑拉出侧边栏

**根因**：`ui/native-shell/.../ui/shell/native/NativeShellRoot.kt:362` → `gesturesEnabled = true` 写死。

**方案**：
```kotlin
gesturesEnabled = subScreenName == null &&
    (screenName == null || screenName == BuiltinPageIds.Settings)
```
即只有聊天页与设置首页（顶栏是 ☰ 的两页）接受边缘滑动；其余页面禁用。宽屏常驻抽屉（`wideLayout`）不受影响。

**验证**：真机 `adb shell input swipe` 逐页：设置→显示与行为、插件页、会话页、模型页、远程页 —— 都不弹抽屉；
聊天页、设置首页 —— 弹；返回键语义不变；抽屉打开时右滑关闭仍可用（那时一定在这两页）。

### 3. 抽屉里的"插件"退出后回到设置

**根因**：`ui/native-shell/.../ui/shell/DshDrawer.kt:392-394` 底部按钮走 `onSelectScreen` →
`NativeShellRoot.kt:82` 的 `go()` 把 `pageFromChat = false`，于是 `backFromPage`（`:130`）一律回设置。

**方案**：把"来源路由"作为显式状态——打开抽屉时捕获 `origin`（`NavRoute`：聊天 / 设置首页 / 当前一级页），
抽屉发起的导航完成后，`backFromPage` / `closeSub` 按 `origin` 返回，不再固定回设置。设置页内部进二级页仍回设置。

**验证**：聊天开抽屉→插件→系统返回/左上角返回 都回聊天；聊天开抽屉→会话→返回回聊天；
设置首页开抽屉→插件→返回回设置；设置→显示与行为→返回回设置（现状不回归）。

### 4. 未启用 / 已删除的插件仍出现在"角色"里

三个独立根因：

**(a) 导入即启用**：`app/src/main/java/xin/dshaa/nativeapp/data/PluginStore.kt:429` → `enabled = true`。
→ 按用户第 5 条改为**默认停用**。注意内置 bundled 插件（`BundledPlugins.ensureWhaleShell` 等）保持各自原有安装语义，别误伤。

**(b) 角色 tab 不过滤停用项**：`ui/native-shell/.../ui/plugins/PluginsScreen.kt:280-321`
把 `enabled=false` 的也列出来（"不可用 · 插件已停用"），计数也算进去。
→ 只列「已启用 + 有授权」的第三方实现；内置实现按内置开关；全无可用时保留"没有可用实现 + 恢复"那一行；计数只算可见项。

**(c) 停用/删除不清角色选择**：`app/src/main/java/xin/dshaa/nativeapp/chat/AppViewModel.kt:6802` 的 `deletePlugin`
只删目录/清单/投影，`dsh_storage` / `dsh_prompt` / `dsh_agent` / `dsh_shell` / `dsh_loading` 原样保留 →
角色 tab 出现红字"未安装存储插件 xxx（没有声明 storage/v1 的启用插件）"，聊天页顶部横幅，
而且 `roleSafetyError`（`AppViewModel.kt:3928`）会**直接拦下发送**，必须手动点"恢复内置"。

→ 抽宿主共享函数 `clearRoleSelection(pluginId)`：清 `dsh_shell/dsh_agent/dsh_storage/dsh_prompt/dsh_loading`
（含 `dsh_loading` 快照与调试键 `debug_llm_provider`）→ 回退内置/native/跟随协议 → 清 safetyNotice →
重解析（存储要换绑路由壳并 `refreshSessions`）。**停用和删除都调用它**，UI 与 AI 工具共用。

**(d) "角色"范围含助手配置**（用户第 4 条"包括"）：
`ui/native-shell/.../ui/settings/AssistantScreen.kt:352-500` 的「插件预设」「插件自带的助手配置/注入段」
不再列停用/已删除插件；套用后生成的角色卡是独立副本，保留。

**验证**：JVM 补路由过滤 + 清理单测；真机：装插件→角色里没有→启用→出现→关掉→消失→选中后删除→无残影、
横幅消失、能正常发送、插件页计数正确。

### 5. AI 也要能删除 / 启停插件

**现状**：`app/src/main/java/xin/dshaa/nativeapp/data/PluginDevTools.kt:93-98` 已有 `plugin_dev_enable`

- 新增 `plugin_dev_delete {id}`，进 `writeNames`，按写工具走审批卡（用户第 8 条）。
- 删除闸门（用户第 7 条 A）：默认拒绝删除正在使用/运行中的插件并返回原因；模型先 `plugin_dev_enable{enabled:false}`，
  停用后即可删。UI 删除确认弹窗保留，确认后内部可带 force。
- 更新随包技能：
  - `support/src/main/assets/skills/dsh-plugin-authoring/SKILL.md`：步骤 L13-16、工具表 L24-32 补 delete；
  - `app/src/main/assets/skills/dsh-plugin-adapter/SKILL.md`：能力清单 L130-134 同步一句。
  （`BundledSkillSync` 会让随包技能随 APK 升级，改 asset 即可。）

**验证**：JVM（临时目录装→删→`plugin_dev_list` 查不到、角色选择清空）；
`PluginDevSelfTest`（L31-54）补 delete 段；真机对话里让 AI"关掉 X / 删掉 Y"，核对角色 tab、插件页计数、发送正常。
