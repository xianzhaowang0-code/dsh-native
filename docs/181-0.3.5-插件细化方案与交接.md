## 二、差距：我们只做了 DSH 的第一层

| 层 | DSH 机制 | 鲸歌现状（2026-11-16） |
|---|---|---|
| ① Service 注册/替换 | 同 id 覆盖（tools / prompt / model / storage / shell / agent / projections…） | ✅ 有：`ctx.tools.register`、`ctx.ui.registerShell/Page/Loading`、`ctx.storage.register`、`ctx.agent.register`、`ctx.systemPrompt.register`、`ctx.llm.register`、`ctx.sessionProjections.register`、`ctx.capability.register`、`ctx.commands.register`、`ctx.provide/inject`、`ctx.on`、`ctx.effect` |
| ② Event 瀑布 / 中间件 | `tools/pre-execute`、`tools/execute`、`tools/post-execute`、`tools/result`、`agent/pre-step`、`agent/request`、`llm/stream`、`system-prompt/assemble`；`ctx.tools.restrict()`（只能删）、`ctx.tools.guard()`（只能拒） | ❌ 只有**只读** `ctx.on('turn/start'|'session/event'|'*')`，不能改写/否决/包装；工具只能**新增**、冲突「先注册生效」；提示词段只能加不能改内置段；`prompt.context` 是 apply 时快照 |
| ③ Client Slot | 命名 slot + `ctx.slots.inject/register`（`conversation.composer.dock`、`conversation.chat.node`、`shell.overlay`…） | ❌ 只有整壳替换、整页替换、加载页树、独立 `dsh.client` WebView 窗口；**不能往原生页里加一块** |
| ④ Patch 层 | `cordis.patch.yml` 按 id 覆盖/插入/禁用、`!!js`、`isolate` | ⚠️ 只做**只读解析**（M61/M74，助手预设展示），不能应用 |

结论：**0.3.5 的目标不是再增加角色种类，而是补上 ②③④ 三层，让插件能改「电器内部」。**

## 三、协议设计

### 3.1 通用规则（所有新扩展点共用）

1. **注册顺序 = 插件启用顺序**（插件列表顺序，同级再按注册先后）；不引入隐式优先级，避免"谁赢说不清"。
2. **中间件签名**：JS 侧 `async (payload, next) => result`。
   - 不拥有决策的中间件**必须** `await next()`（返回它的结果），可先改写 payload；
   - 返回 `null`/`undefined` = 放弃改写，继续链；抛异常 = **本中间件跳过并在诊断里记错**，不影响其他插件与主流程；
   - 同步快速路径：`guard/restrict/describe` 用同步签名，不进 Promise 队列。
3. **超时预算**：单次 JS 往返默认 **50ms**（可在设置里 20–500ms 调）；超时视为跳过 + 记诊断；工具执行本身不受此限。
4. **权限**（新增 manifest 权限，默认**需确认**）：
   - `tools:intercept`（改参数/结果/描述，危险：能伪造证据）
   - `llm:request`（改请求/流，危险：能改模型看到的全部内容）
   - `ui:slot`（往宿主界面加块，危险程度低，但能模仿宿主 UI 骗取点击 → 仍要确认一次）
   - `storage:hooks`（写钩子，危险）
   - 收紧类（`restrict/guard`）**导入即允许**：只能让权限变小。
5. **卸载**：所有注册挂在 `ctx.effect` 语义上；插件停用/删除/崩溃，中间件与槽位按注册逆序移除；会话不需要重开。
6. **零插件零开销**：没有插件注册时，中间件链为空，**请求体/工具清单/提示词与 0.3.4 逐字节相同**（用现有 parity 工具回归）。
7. **诊断**：插件页新增「扩展点」页签，逐链展示：注册者、顺序、命中次数、耗时、跳过/异常、改写前后哈希；logcat 统一 tag `DshExt`。设置里加「插件中间件」总开关（关了全部旁路，用于排障）。
8. **落盘是唯一真相**：中间件只改"这一次请求/这一次工具结果"，不改写会话历史；改写工具结果时，**工具卡展示原始结果 + 「已由 <插件> 改写」标记**，并记录原始内容哈希，避免证据失真。

### 3.2 工具内部（M87-A）

```js
ctx.tools.restrict(['bash', 'shower_*'])        // 只能删（会话/代理级）
ctx.tools.guard('bash', (call) => call.args.command.includes('rm -rf')) // 同步拒绝
ctx.tools.describe('bash', { description: '...', parameters: {...} })  // 改 schema/描述

ctx.tools.on('pre-execute', async (call, next) => {   // 改参数 / 返回 { allow:false } / { ask:true }
  return next({ ...call, args: rewrite(call.args) })
})
ctx.tools.on('post-execute', async (res, next) => {   // 改结果 text/images/isError
  return next({ ...res, text: res.text.replace(/example\.com/g, 'mirror.local') })
})
ctx.tools.on('result', (res) => { /* 只观测，不可改 */ })
```

- 宿主落点：工具清单在 `AppViewModel.kt` 的 `apiTools = { … }`（2199 / 7407 两处）——先过滤 `restrict` 再套 `describe`；执行在 `TurnEngine.kt` 758–763（`parseArgs` → `registry.execute`）之间插 `pre-execute`，执行后插 `post-execute`；`approval`（741 行）之前插 `guard`（同步拒绝，文案进 tool 卡）。
- 验收：被 restrict 的工具不出现在请求 tools[] 且模型看不到；guard 拒绝落 `tool/result`（isError）；post-execute 改写后模型拿到改写值、tool 卡有改写标记；停用插件后请求体恢复原样。

> **实现修订（2026-11-16，M87-A 二批）**：`ToolMiddleware.guard` 为 suspend——JS handler 仍写同步函数，
> 宿主只是把这次 50ms 往返放到 IO 线程（`restrict/describe` 仍走同步元数据快速路径）；v1 `post-execute`
> 只改 `text/isError`，图片保持原样；插件需重新导入/加载后才有 `PluginRecord.toolMiddleware` 记录。
> 证据见 `docs/181-evidence/m87a-batch2-jvm.md`。
>
> **真机验收修订（2026-11-16 第五棒，设备 `192.0.2.10:33337`）**：真机 fixture 抓到 3 个实现缺口，
> 已在 `f791a82` 修复：① `PluginRecord.toolMiddleware` 之前没落盘，带 `tools:intercept` 的插件安装会
> 「插件清单写入失败」；② guard/pre-execute 的 JS 侧读 `payload.call`，宿主却直接发 call 对象 →
> guard 永远放行、pre 永不生效，现统一包 `{call}`；③ restrict 只从 `tools[]` 删，模型幻觉/提示注入
> 直接点名仍会执行，现执行前也查 `allowsTool` 并落 isError 结果。另：`ui:slot` 不再显示「未识别」
> （新增 `UI_SLOT`，M87-C 前只识别不生效）；guard/restrict 拒绝在工具卡显示红色错误而非绿色对勾。
> 真机证据：`docs/035-4-evidence/`（未跟踪）。

### 3.3 请求 / 提示词内部（M87-B）

```js
ctx.on('agent/request', async (req, next) => {   // 改 messages/tools/model/params
  return next({ ...req, model: pickModel(req) })
})
ctx.on('llm/stream', async (flow, next) => {     // 流式改写（包一层）
  return next(transform(flow))
})
ctx.on('system-prompt/assemble', async (prompt, next) => {  // 有序拼装，可替换内置段
  return next(prompt.replace(SECTION, NEW_TEXT))
})
ctx.on('agent/pre-step', async (step, next) => { /* 注入/裁剪本步消息（等价 agent.inject） */ })
```

- 宿主落点：`TurnEngine.kt` 1014 / 1045 的 `ApiRequest(...)` 构造后、`deps.stream` 调用前；`systemPrompt()`（App 侧 PromptPack 组装）与 `apiTools()` 同层。
- 约束：`agent/request` 只改**本次请求副本**，不改 `ui.messages()`；改写后的请求仍走 `onRequest` 落 `run.jsonl`（调试可回放）。
- 验收：model 路由插件按 session 选不同模型（run.jsonl 两份请求体不同）；prompt 替换内置段后请求体变、会话历史不变；流式中间件把 `foo`→`bar` 后 UI 与落盘一致。

### 3.4 UI 插槽（M87-C/D，重点）

第一版槽位清单（够用、可验证，不追求一次铺满）：

| slot | 位置 | 形态 |
|---|---|---|
| `chat.composer.dock` | 输入条上方一行（或下方图标条） | Surface 子树 + 只读状态 |
| `chat.node.<kind>` | 指定消息类型（tool 卡 body / assistant footer / user footer） | 只读展示 |
| `chat.message.actions` | 消息长按/更多菜单项 | 按钮 + 动作 |
| `settings.rows` | 设置首页/指定子页追加行 | 行 + 开关/跳转 |
| `drawer.items` | 侧边栏底部追加项 | 行 + 跳转 |
| `shell.overlay` | 全局浮层（最后一个注册的置顶） | 受限浮层 |

```js
ctx.ui.slots.register({
  slot: 'chat.composer.dock', id: 'my.mirror-btn', order: 100,
  when: { session: 'any' },
  tree: { type: 'row', children: [ { type: 'button', text: '镜像模式', action: 'toggle' } ] },
  bindings: { mirrored: 'wire.mirror.enabled' },
})
ctx.ui.slots.action('my.mirror-btn/toggle', async (payload, host) => { … })
```

- 形态：**声明式 Surface 子树**（复用 `app/.../ui/surface/SurfaceRenderer.kt`），禁止插件注入任意 Compose/WebView；节点上限沿用 loading/v1 的预算（单插件 ≤64 节点、深度 ≤12、单文本 ≤2000）。
- 数据：只读绑定 session projection 的 `wire.view`（客户端不折叠事件）；动作用 `slots.action` 回到插件 JS。
- 隔离：任一槽位渲染异常只摘掉该项并显示占位（不白屏）；`when` 不满足时不渲染、不回调。
- 落地：`ui/shell-api` 新增 `SlotRegistry`（共享模块，参照 `RoleTargetVisibility.kt` 的放法）；`NativeShellRoot` / `ChatScreen` / `ChatComposer` / `SettingsScreen` / 抽屉 插入渲染点；`app` 侧把插件注册的树同步到 registry（停用即清）。
- 验收：装 fixture 后聊天页输入条出现按钮、点按回插件 JS 且状态往返；工具卡 body 出现附加行；设置页多一行；停用插件后 UI 恢复原样且无残留白块。

### 3.5 存储 / 事件内部（M87-E）

```js
ctx.storage.on('before-append', async (event, next) => {   // 可拒绝/改字段（不改 type）
  return next(event)
})
ctx.storage.on('after-load', async (session, next) => next(session))
ctx.on('session/event', async (e, next) => { /* 可 veto：return null；可改写 ignorable 字段 */ })
```

- 事件瀑布只对 `ignorable` 的插件记录开放改写；**普通会话事件不可 veto**（否则会破坏日志一致性）。
- storage v1 仍只读；写钩子先只做 `before-append` 的**观测 + 拒绝**，不做改写（改写写路径放到 0.3.6 评估）。
- 验收：before-append 拒绝时 tool/user 消息不落盘且 UI 提示；事件 veto 的只有插件记录；重启后日志可重开。

### 3.6 包格式、零代码与表现自由（M87-G）

> 用户 2026-11-16 追加反馈：插件「格式别扭、只能写代码、形式和表现形式被束缚」，要求包格式自由一些。
> 拍板：载体自由 / 零代码 / 表现自由**都做**，能兼容尽量全兼容；**并入 0.3.5**；统一 IR + 鲸歌轻格式 + DSH 包兼容。

#### 3.6.1 统一包 IR

内部只认一种模型，外部多入口：

```text
PluginPackage {
  id, name, version, format,              // format: whale-lite | dsh | legacy-js
  permissions: [string],
  contributions: [ { kind, id, config, assets } ]
}
```

- 安装入口（文件夹 / `.zip` / `.dshpkg` / 单 `.md` / 单 `.json` / 单 `.yaml` / DSH 的 `package.json`）
  统一解析成 IR，再落 `PluginStore`（新增 `format`、`contributions` 字段，旧字段语义不变）。
- 旧鲸歌插件（目录 + `index.js`）与 DSH 包都映射成 IR 里的一条 `kind: script`（+ `client`）贡献，
  **加载、权限、启用、角色行为与 0.3.4 完全一致**（对拍清单里每个插件的 id/权限/角色不变）。
- 未知 kind / 未知字段：**不装、不猜**；可读中文校验错误指向具体路径与行。

#### 3.6.2 第一版 kinds 与入口推断

| 入口 | 推断 |
|---|---|
| `.md`（frontmatter 里 `kind/name/...`） | `skill` 或 `prompt` |
| `.json` / `.yaml`（顶层 `kind`） | `theme` / `preset` / `page` / `macro` / `mcp` / `tool.http` |
| `.zip` / `.dshpkg`（含 `dsh.package.json`） | 完整包（多贡献物 + 素材） |
| DSH `package.json`（`dsh.bundle`/`dsh.client`） | 兼容包：`script` + `client`，`cordis.patch.yml` 收成 `preset` 贡献 |

第一版 kinds：`skill`、`prompt`、`theme`、`page`、`macro`、`mcp`、`tool.http`、`script`、`client`、`asset`（图片/音效）。
每个 kind 一个 JSON Schema + 权限 + 预算（节点数/体积/超时），校验失败给中文原因。

#### 3.6.3 能力阶梯（从零代码到代码）

| 档 | 形态 | 例子 | 写代码？ |
|---|---|---|---|
| 0 | 数据/素材 | 主题 tokens、音效、图片 | 不用 |
| 1 | 声明式 | 提示词包、技能 md、页面 Surface 树、命令宏、MCP 配置 | 不用 |
| 2 | 表达式 | `{{变量}}` / 条件 / HTTP 模板 | 很少 |
| 3 | 脚本 | 现有 `index.js` + `apply(ctx)`（M87-A~E 的新 API） | 要 |
| 4 | 前端资产 | `dsh.client` / WebView 片段 | 要 |

原则：**能用低档不用高档**；高档能做低档的全部事情；低档不需要运行 JS。

#### 3.6.4 零代码工坊

- App 内「插件工坊」：选模板（提示词包 / 主题 / 页面 / 宏 / MCP）→ 表单填写 → 预览 → 导出标准包或直接保存为本地插件。
- 产物就是 3.6.1 的包，不做私有格式；用户之后可手改、可再导入。
- 权限与来源如实展示（本地创建 / 导入 / DSH 兼容），危险权限仍走确认。

#### 3.6.5 表现自由（主题 / 卡片 / 桌宠 / 小部件）

- `theme`：颜色/圆角/字体/间距 tokens + 可选背景图；只影响 token，不注入布局代码。
- `decoration`：挂在 M87-C/D 的 slot 上，用 Surface 子树表达；动效用**声明式关键帧/过渡**（限定属性与帧率），
  **不开放任意 canvas/JS 绘制**；复杂动效留 0.3.6 再议（可能走受限 WebView 专项）。
- 桌宠/小部件：`shell.overlay` / 浮层 slot + `asset` + 帧动画声明；点击/拖动走 `slots.action`。
- 卡片皮肤：`chat.node.<kind>` 的 style 覆盖 + 素材，**不允许改变节点语义**（工具卡仍是工具卡）。

#### 3.6.6 安全与兼容

- 声明式也要权限：`theme`→`ui`（低危）、`page`/`decoration`→`ui:slot`、`macro`→宏内工具权限并集、
  `mcp`/`tool.http`→`net:<host>`、`asset`→无；零代码不等于零风险。
- 兼容：DSH 包原样导入；新字段缺失按旧语义；导入前展示「格式/贡献物/权限」预览。
- 迁移：`PluginStore` 旧记录升级时补 `format=legacy-js`，不重装、不改用户开关。
- **实现修订（2026-11-16 第四棒，M87-G 落地）**：
  - 记录层已有 `format`（0.3.4 起存 `DSH`/`Operit` 展示名），直接改成 `legacy-js` 会丢展示信息；
    因此新增 **`irFormat`**（`whale-lite`/`dsh`/`legacy-js`/`operit`）承载 IR 格式，
    `format` 保留原语义。旧记录读盘时 `irFormat` 补 `legacy-js`，贡献物按
    `main`/`clientUi`/`presets` 补成 `script`/`client`/`preset`——id、权限、开关、角色不变。
  - 第一版额外收了 `preset` kind（DSH `cordis.patch.yml` 的助手预设收成一条贡献物）；
    `decoration` 不在第一版 kind 列表里，出现时按「未知 kind」拒绝（不猜）。
  - 本批只做「解析 + 安装 + 往返 IR 相等 + 插件页展示」；单文件 `.yaml` 与工坊表单 UI、
    theme/page/macro 的运行时生效（依赖 M87-C 槽位）明确延后，本批不假装生效。
  - 鲸歌轻格式（`dsh.package.json`）里声明 `script`/`client` 的包本批**拒绝安装**：
    没有「无 package.json 的 JS 安装」链路，半装比报错更糟；脚本插件请继续用
    DSH `package.json`/旧 `manifest.json`（行为与 0.3.4 一致）。

#### 3.6.7 验收

1. 四个入口各一个 fixture：`.md` 技能、`.json` 主题、`.zip`（page+macro）、真实 DSH 包，全部可装可启用。
2. 零代码主题改色立即生效；声明式页面出现在路由；宏按序执行；MCP 可连（无网络时如实报错）。
3. 工坊创建→导出→再导入，IR 相等（字段级对拍）。
